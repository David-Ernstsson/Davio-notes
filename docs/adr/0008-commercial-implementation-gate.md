# What must exist before commercial implementation starts

Owner-locked 2026-09-21, and corrected the same day. The first lock put approved stills ahead of a spec. That order produced a new picture for every screen. It does not stand.

Production implementation starts only after an explicit go. That go comes after one kit for the core journey, one visual surface on that kit, then the tokens that kit already uses. Later screens are assemblies of the kit. The kit is [screen-consistency.md](../product-experience/screen-consistency.md). Why a generated picture cannot be the kit: [commercial-screen-process.md](../research/commercial-screen-process.md).

The owner approves the kit, then each screen assembled from it. The go is the owner saying implementation may start. Tokens are the values already in the kit, on the phone-first web client ([ADR-0007](0007-phone-web-commercial-client.md)). They are not a full design system, and they are not the Atlas pile promoted into the product.

**Considered Options:** a new generated picture for every screen; a full specification of every later screen before any code; starting implementation from the Atlas prototype. Rejected. A new picture is a new product. A thick spec freezes unapproved screens. The Atlas pile is throwaway, and implementation is a rewrite of the approved journey.
