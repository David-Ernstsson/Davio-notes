# The server holds a signed-in Learner's progress; the phone counts free starts

Owner-decided 2026-11-15 in [#144](https://github.com/David-Ernstsson/Davio/issues/144). The full model is [accounts and progress](../product-experience/accounts-and-progress.md). Three of its choices would look wrong to a later reader without the reason.

**The Learner has Davio's own ID, and Google is one way into it.** V1 has Google sign-in only, so the Google account could have been the Learner. Apple or email and password are likely later, and moving every Learner's data to a new key then costs far more than one extra table now. A purchase receipt is attached to the Davio ID, one Learner at a time, and moves to whoever signs in on the phone that holds it. Fixing it to the first Learner was rejected: it needs support work and can leave progress on one account and the subscription on another.

**The server is the record for a signed-in Learner, but only for finished lessons.** The phone keeps a working copy and sends finished lessons, each with an ID made on the phone, until the server confirms. Because finished lessons are only ever added, two copies combine without conflict, including a guest's progress merging into an account. The unfinished current lesson stays on its phone. Syncing it was rejected: it brings two phones answering one lesson offline, for a case almost no Learner has.

**The phone counts the free starts, and the allowance never requires a connection.** The server counting them was considered and would stop a Learner getting extra starts by changing the phone's clock. It was rejected because the gain from cheating is two more lessons of a free product, while what costs money sits behind Plus, which the server does check. It would also tie starting a lesson to the server being reachable, which should depend only on whether the lesson's files are on the phone. That keeps offline lesson sets possible later. The two starts come back at local midnight or 24 hours after the first counted start, whichever is sooner, so crossing time zones never lengthens the wait.
