# Production platform options

**Answer.** Keep one phone-first web client and compare two .NET arrangements first: Azure Container Apps with Azure SQL, and a small paid Render container with managed PostgreSQL. Keep Cloudflare Workers with D1 as the low-cost TypeScript comparator, not a reason by itself to discard the founder's .NET expertise. All three can serve the required product; none supplies progress merging, offline semantics or subscription ownership automatically. Approximately EUR 20/month is plausible for a small infrastructure footprint, not established for Davio's total operation. For Play packaging, investigate Capacitor first when predictable local storage and Android integrations matter most, and TWA/Bubblewrap when the smallest wrapper and remotely updated web client matter most. Prove billing, Google sign-in and offline recovery on devices before choosing. This is a provisional research recommendation, not an owner-approved architecture. Evidence and qualifications follow in [Requirements](#requirements), [Hosting shortlist](#hosting-shortlist), [Play packaging](#play-packaging) and [Costs](#costs).

Researched 2026-10-16 for [Which production platforms fit Davio requirements and a solo .NET maintainer?](https://github.com/David-Ernstsson/Davio/issues/141), under [Plan Davio production architecture and the transition to launch](https://github.com/David-Ernstsson/Davio/issues/140). Prices are public USD list prices unless stated otherwise. Official sources were checked on that date; reprice the selected region/account before committing. No provisioning or implementation was performed.

### What the prototype establishes

The [current Cloudflare deployment script](../../scripts/deploy-cloudflare.ps1) builds `prototypes/explore-hall`, uploads static assets and routes evaluation through a Pages Worker. Its [build](../../prototypes/explore-hall/build-hosted.mjs) routes `/api/*` dynamically; its [client](../../prototypes/explore-hall/app.js) saves run state in `localStorage` and fetches lesson data. The [hosted worker](../../prototypes/explore-hall/hosted-worker.mjs) invokes the [model bridge](../../prototypes/explore-hall/hosted-model-bridge.mjs) for Compose. Its cache, concurrency and rate counters are in process memory and explicitly described as demo throttling, not a global spending limit. The [judge](../../prototypes/explore-hall/compose-judge.mjs) preserves rule/provenance information and returns `unchecked` on technical failure. These are useful contract examples, not evidence that production identity, durable state, global limits, billing or offline relaunch already work. Inspection baseline: `5468a509abaafa93570cdd0aba426c824bb9c621` on `origin/master`.

### Publish remains the release boundary

[Publish](../product-pack/CONTEXT.md) and [product ADR 0030](../product-pack/docs/adr/0030-publish-delivers-freeze-to-learner-app.md) already mean: freeze Studio Edition membership, package Activity JSON and required Piper Resource TTS (Gemini optional), deliver a PR into the learner-app repo, and let the operator merge. [ADR 0029](../product-pack/docs/adr/0029-staging-living-catalog-publish-freezes-edition.md) retains prior selectable Editions. A direct Studio-to-live-bucket upload would change that contract.

**Derived deployment option:** after the existing PR merges, CI may validate compatibility/hashes/resources, upload immutable Edition objects, then activate a small release manifest. Keep the prior manifest and referenced bytes for rollback and unfinished runs. This preserves Publish while allowing content updates without another Play binary. Validation policy, activation authority and offline quarantine behaviour remain decisions in [Decide how Studio Editions reach learners safely](https://github.com/David-Ernstsson/Davio/issues/145); this note does not select a new transport.

## Hosting shortlist

The same static/media delivery can accompany any API. Keep learner data in the database and published media in object storage; this is a proposed separation, not a schema lock.

| Arrangement | Why credible for Davio | Maintenance/cost trade-off |
| --- | --- | --- |
| **Azure: ASP.NET API on Container Apps Consumption + Azure SQL Database** | Preserves C# and SQL Server tooling. Microsoft documents [C# container deployment](https://learn.microsoft.com/en-us/azure/container-apps/quickstart-code-to-cloud); Azure SQL is managed. | Strong familiarity; more separately metered Azure resources. Scale-to-zero can put API and database warm-up on the same request. Quote a tiny paid DTU database as well as serverless/free. |
| **Render: ASP.NET Docker service + paid managed PostgreSQL** | Render supports [.NET through Docker](https://render.com/docs/native-runtimes), [managed Postgres](https://render.com/docs/postgresql-creating-connecting), private networking and [container deployments](https://render.com/docs/docker). | A simple always-on baseline with a different SQL dialect. Founder owns container/runtime upgrades and migrations; vendor owns database hosting. Smallest instances require memory/load verification. |
| **Cloudflare: TypeScript Worker + D1 + static assets/R2** | Matches the demo's hosting family; [Workers languages](https://developers.cloudflare.com/workers/languages/) and [D1's SQLite semantics](https://developers.cloudflare.com/d1/) are documented. | Low fixed floor, little host administration; trades away ordinary ASP.NET hosting and SQL Server/Postgres compatibility. D1-specific access/limits need deliberate acceptance. |

### Azure: familiarity without assuming free production

[Container Apps billing](https://learn.microsoft.com/en-us/azure/container-apps/billing) includes 180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million requests per subscription/month on Consumption. Zero replicas incur no resource charge; running replicas, including eligible idle replicas, can incur charges. Other resources are extra. A deployment quickstart also creates a registry and Log Analytics workspace: count them, network transfer and monitoring, rather than treating the compute grant as the whole bill. Obtain regional rates from [Azure pricing](https://azure.microsoft.com/pricing/details/container-apps/).

[Azure SQL's current free offer](https://learn.microsoft.com/en-us/azure/azure-sql/database/free-offer?view=azuresql) supplies 100,000 vCore-seconds and 32 GB each of data and backup storage per database/month for the subscription's lifetime. It is not merely a 12-month trial. At the limit it can pause until next month, or charge standard serverless overage; switching to paid overflow cannot be reversed to the monthly-stop option. The stop option has seven-day PITR, local backup redundancy and no long-term retention. Leaving connections open can prevent normal auto-pause. That makes it useful for evaluation, but quota exhaustion is a production availability decision, not a free substitute for one.

[SQL purchasing models](https://learn.microsoft.com/en-us/azure/azure-sql/database/purchasing-models?view=azuresql) include fixed DTU packages as well as provisioned/serverless vCores. [Serverless](https://learn.microsoft.com/en-us/azure/azure-sql/database/serverless-tier-overview?view=azuresql) bills a minimum while awake and can delay requests when resuming. The free allowance is about 27.8 one-vCore hours, not a continuously available month. Do not extrapolate request count directly into that allowance. A paid Basic/Standard DTU quote may be a better small-production comparison than unbounded General Purpose serverless.

### Render/Postgres: a small paid baseline

[Current pricing](https://render.com/pricing) lists a `0.5c-512mb` web service at $7/month and `0.1c-256mb` Postgres compute at $6/month, plus database storage at $0.30/GB-month. [Compute docs](https://render.com/docs/compute-plans) map these to the former Starter and Basic-256mb names. With **one always-on API instance and 1 GB provisioned database storage**, that is **$13.30/month before transfer, builds, media, tax and other services**. This is a configured footprint, not an estimate of how many learners it serves. [Hobby](https://render.com/docs/platform-features-by-plan) has no workspace fee and allows one member; some operational features need Pro. [Storage](https://render.com/docs/postgresql-creating-connecting) grows separately and cannot be shrunk in place.

[Paid backup recovery](https://render.com/docs/postgresql-backups) offers three-day PITR on Hobby and seven days on Pro; recovery creates another database to validate and reconnect. Free Postgres has no managed recovery, expires after 30 days and is deleted after its 14-day grace period. [Free web services](https://render.com/docs/free) sleep after 15 idle minutes and take about a minute to wake. Exclude this free combination from the production baseline.

PostgreSQL does not require abandoning C#: the [Npgsql EF Core provider](https://www.npgsql.org/efcore/) supports .NET. SQL dialect, migrations, timestamp/JSON behaviour and operational tooling still need learning. This is a credible relational alternative, not a claim that changing databases is costless.

### Cloudflare/D1: cost comparator with a different backend

[Workers Paid](https://developers.cloudflare.com/workers/platform/pricing/) has a $5/month account minimum, including 10 million requests and 30 million CPU milliseconds; overage is $0.30/million requests and $0.02/million CPU milliseconds. Direct static-asset requests are free; routing through caching/dynamic execution has different billing. Free Workers are limited to 100,000 requests/day and 10 ms CPU/invocation.

[D1 Paid pricing](https://developers.cloudflare.com/d1/platform/pricing/) includes 25 billion rows read, 50 million written and 5 GB storage/month; overage is $0.001/million reads, $1/million writes and $0.75/GB-month. Scanned/indexed rows matter, not just returned records. Free daily query exhaustion returns errors. [Limits](https://developers.cloudflare.com/d1/platform/limits/) include 10 GB per paid database versus 500 MB free, with queries processed serially per database. [Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/) gives 30-day recovery paid and seven days free; restore overwrites the database and interrupts queries. Export and rehearse recovery independently of rollback of content.

## Play packaging

| Concern | TWA / Bubblewrap | Capacitor Android shell |
| --- | --- | --- |
| Web client and updates | Browser renders the hosted site. Web deployment changes the app experience; wrapper/signing changes still need Play releases. | Bundle the web UI in an Android app; native/plugin changes need binary updates. Fetch Edition data remotely. |
| Play billing | Chrome's Digital Goods API and Payment Request bridge; detect availability. It is not ordinary web card checkout. | Native Play Billing through a maintained plugin or a small native bridge; plugin support is a selection cost. |
| Google sign-in | Browser-based Google Identity flow; test redirect and account selection inside the actual TWA. | Native credential integration or external system-browser flow with a verified return path. Embedded WebView OAuth is forbidden. |
| Current Activity offline | Service worker plus cached shell/content/audio and durable run data; first launch needs special handling. | Bundled shell, local files and durable local data; remote content still needs transactional download/readiness. |
| Reminders | Web Push requires subscription, a service worker and a sender; do not promise a local timer while a web page is closed. | Local notifications can schedule an optional daily reminder without a push server; FCM is available when remote push is needed. |

Sources: Google's [PWA-to-Play guide](https://developers.google.com/codelabs/pwa-in-play), [TWA integration](https://developer.chrome.com/docs/android/trusted-web-activity/integration-guide/), [TWA billing](https://developer.chrome.com/docs/android/trusted-web-activity/receive-payments-play-billing/), [offline-first TWA](https://developer.chrome.com/docs/android/trusted-web-activity/offline-first), Capacitor [Play deployment](https://capacitorjs.com/docs/android/deploying-to-google-play), [updates](https://capacitorjs.com/docs/guides/deploying-updates), [storage](https://capacitorjs.com/docs/guides/storage), [plugins](https://capacitorjs.com/docs/plugins/android), [local notifications](https://capacitorjs.com/docs/apis/local-notifications), [push](https://capacitorjs.com/docs/apis/push-notifications), Google [OAuth policy](https://developers.google.com/identity/protocols/oauth2/policies) and [Web Push overview](https://web.dev/articles/push-notifications-overview).

**TWA qualifications:** Google's billing page currently documents Digital Goods support only in Chrome inside a TWA. Detect support and prove the approved fallback; a different browser must not silently strand purchase/restore. Digital Asset Links must match the Play signing certificate and owned HTTPS origin. The PWA remains a public website: Google explicitly says it cannot reliably distinguish wrapper access from browser access. "Play is the production entry point" is compatible with this; "nobody can run the client outside Play" would be an additional requirement needing a decision. The first offline launch has no registered service worker, although V1 only promises offline use after resources load. Sources: the Google guides above.

**Shared acceptance work:** neither package makes cached files durable by magic. Web storage is quota/eviction dependent; request persistent storage and handle refusal/full storage. Capacitor recommends native storage for durable data, with Preferences for small values and a fuller store for larger data. Pin the current Activity's Edition, cache its required resources before counting a start, persist its run, and recover after process death. Verify on a real device after airplane mode, force-stop, update and low-storage conditions. Sources: [browser storage](https://web.dev/articles/storage-for-the-web), [Capacitor storage](https://capacitorjs.com/docs/guides/storage).

Published audio files suit both packages; don't replace Piper/Gemini Resources with runtime device speech as an accidental implementation shortcut. Handle media `play()` rejection and keep a manual play control; test interruptions and resume. [Chrome's autoplay guidance](https://developer.chrome.com/blog/autoplay/) does not guarantee every playback will start. Google Play [in-app review](https://developer.android.com/guide/playcore/in-app-review) and accessibility also belong in the device trial. Daily reminders can be inexact; Android notification permission/Doze restrictions still apply. A paid live-update service is not required just to download content data.

For **either** wrapper, [Google's payments policy](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en) covers education subscriptions and normally requires Play Billing; regional alternative-payment programs have separate enrollment/terms. Use ordinary Play Billing as the comparison baseline. [Verify purchases on a secure backend](https://developer.android.com/google/play/billing/security), grant only purchased entitlements and [acknowledge promptly](https://developer.android.com/google/play/billing/integrate). [Real-time developer notifications](https://developer.android.com/google/play/billing/rtdn-reference) use Pub/Sub and signal a change; fetch authoritative status from the Developer API. Their handling belongs in any hosting topology, including reconciliation after outages. Separately [verify Google identity tokens](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token); Play's purchasing account and the app's Google account need not be the same. A billing intermediary may reduce code but adds another vendor/cost; none is assumed here.

## Costs

| Cost bucket | Include before calling the result affordable |
| --- | --- |
| Fixed/provisioned | API/database baseline, domain renewal divided over a year, paid workspace/monitoring minimums if selected. Extra staging environments and recovery instances count. |
| Usage | API CPU/memory/runtime/requests, database growth, media operations/transfer, evaluation tokens/retries, logs/retention, builds, backups and Pub/Sub. |
| Content production | Piper/Gemini preparation and editorial operation are distinct from serving already generated clips. Do not charge synthesis on every replay in the model. |
| Store/payment | Registration, transaction/service fees, taxes/refunds/adjustments; any billing-service fee. Separate from the infrastructure comfort point. |
| Currency/tax | USD rates are not EUR charges. Record region, FX date, VAT treatment and whether EUR 20 means invoice total or cost after recoverable tax. No FX conversion or Swedish VAT assumption is made here. |

[R2 Standard](https://developers.cloudflare.com/r2/pricing/) is a shared media candidate: 10 GB-month storage, 1 million Class A and 10 million Class B operations/month included; then $0.015/GB-month, $4.50/million A and $0.36/million B, with free Internet egress. Operations and billing-unit rounding still matter. Infrequent Access has different retrieval/minimum-duration terms and no equivalent free tier. Use a production domain/access design, not a development URL as the release contract.

For example, **one Render API + 1 GB database**, free static hosting and **R2 usage below all its allowances** start at the $13.30 footprint above. That leaves unpriced headroom toward EUR 20, not a promised total. The **Cloudflare $5 account floor** similarly describes only a configuration remaining within included usage. Azure has no single honest total until region, SQL tier, replica policy, registry and logs are quoted. These are small-start comparisons without high availability or a second paid environment. [Firebase pricing](https://firebase.google.com/pricing) lists FCM as no-cost; the server/scheduler and notification integration still have operating cost.

Google charges a [$25 one-time Play developer registration fee](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en) if a new account is needed; an existing `com.davio` listing is not evidence that another fee or listing is necessary. As of this research, [Play's fee table](https://support.google.com/googleplay/android-developer/answer/112622?hl=en) lists auto-renewing subscriptions at 10% service plus 5% billing in the updated regional schedule, and 15% in remaining markets: **15% combined for the ordinary Play Billing subscription baseline**. Regional/program terms can change this. [Google handles EU consumer VAT for Play digital purchases](https://support.google.com/googleplay/android-developer/answer/138000?hl=en); EUR 7.99 is not all available to pay infrastructure, and tax/accounting obligations are not exhausted by that handling. Do not infer founder net revenue with a universal VAT percentage.

**Cost model to fill after the owner chooses a shape:** starts × required downloads × bytes/clip and cache misses; evaluations × attempts/retries × input/output tokens; API calls × measured CPU/memory/awake time; retained evidence × size; plus logs, backups and fixed costs. Set independent evaluation and abuse limits: [Azure budgets alert without stopping consumption](https://learn.microsoft.com/en-us/azure/cost-management-billing/costs/tutorial-acm-create-budgets). Prefer a sustained small production workload measurement over a vendor's demonstration of a free idle project.

## Decisions exposed and next evidence

1. **Backend/database:** take Azure .NET/SQL and Render .NET/Postgres into [Choose the production client, API, database and hosting shape](https://github.com/David-Ernstsson/Davio/issues/142). My provisional preference is to retain .NET and compare an actual small Azure SQL quote with Render's paid baseline; choose Cloudflare-native only if its whole maintenance/price trade-off wins for the owner. Managed SQL Server is not inherently ruled out by this budget.
2. **Packaging:** resolve TWA public-origin access, Chrome billing fallback, versus Capacitor's plugin/Android maintenance in [Choose how the phone-first web app ships and updates through Google Play](https://github.com/David-Ernstsson/Davio/issues/143). A small signed device trial must cover Google sign-in, purchase/pending/restore/cancel, offline relaunch with audio, and an update during a current run. This research does not approve a wrapper or replace existing `com.davio`.
3. **Offline evaluation conflict:** the foundation promises the current Activity offline; the prototype Compose evaluator calls a remote model. Decide exactly what remains usable/unchecked offline and how retry/sync works in [Decide how evaluation and audio operate within offline and cost constraints](https://github.com/David-Ernstsson/Davio/issues/146). Do not fabricate a grade or quietly remove the offline promise. The choice affects model cost more than the small hosting minimum.
4. **Ownership/release:** guest progress merge, purchase account mismatch, reinstall/deletion, allowance idempotency and stale offline entitlements belong in [Decide ownership and recovery of learner progress, accounts and subscriptions](https://github.com/David-Ernstsson/Davio/issues/144). Immutable content delivery/activation and old-client compatibility belong in [Decide how Studio Editions reach learners safely](https://github.com/David-Ernstsson/Davio/issues/145). Immediate remote quarantine cannot reach an offline device; specify the reconnect/expiry policy explicitly.
5. **Operation:** choose acceptable downtime/data loss, retention, export/restore rehearsal, alerts, support escalation, data region/processor terms and hard spending controls in [Define the minimum reliable and affordable production operation](https://github.com/David-Ernstsson/Davio/issues/147). Short free/entry-level recovery windows and single instances are trade-offs, not equivalent to high availability. Price the chosen operating level before locking the budget, then sequence the transition in [Sequence the transition from prototype to a production-ready app](https://github.com/David-Ernstsson/Davio/issues/148).

There is no need for a broader provider survey before those decisions. This note changes no product glossary, runtime ADR, launch offer or implementation gate.
